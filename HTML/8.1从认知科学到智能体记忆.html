8.1.1 · 认知科学模型

人类记忆的层次结构

认知心理学把记忆分成三层，每一层都有自己的容量、寿命、用途

感觉记忆 SENSORY MEMORY
0.5 – 3 秒
容量巨大，保存感官接收到的全部信息
工作记忆 WORKING MEMORY
15 – 30 秒 · 7±2 项
负责当前任务的信息处理
长期记忆 LONG-TERM MEMORY
可达终生 · 容量近无限
细分为程序性 / 陈述性
程序性 PROCEDURAL
技能与习惯（如骑自行车）
语义记忆 SEMANTIC
一般知识与概念（"巴黎是法国首都"）
情景记忆 EPISODIC
个人经历与事件（"昨天的会议"）
三类核心 + 程序性记忆 → 共四类长期记忆子类型

8.1.2 · 两大根本性局限

LLM 的两个短板

借鉴人类记忆，我们可以看清 LLM 智能体为什么必须外挂记忆与检索

LIMITATION 1

对话状态的遗忘

LLM 本身是无状态的——每一次请求都是独立的计算，不会自动"记住"上一轮内容。

后果：上下文丢失 · 个性化缺失 · 学习能力受限 · 前后矛盾
LIMITATION 2

内置知识的局限

LLM 的知识是静态、有限的，全部来自训练数据——天然带截止时间和覆盖面。

后果：时效性差 · 专业深度不足 · 容易幻觉 · 缺少来源

8.1.2 · 局限 2/2 · 知识局限

静态知识：截止时间 + 覆盖面

时效性

训练截止

大模型的训练数据有截止点，无法获取最新信息——昨天的新闻它听都没听过

用实时检索补
深度

专业领域

通用模型在垂直领域（医学、法律、论文）深度知识可能不足——样样通、样样松

用专业语料补
事实

幻觉风险

模型可能编造看似合理但并不存在的事实——"一本正经地说错话"

用检索验证补
来源

可解释性

直接问 LLM 它答不出"为什么这么说"，只能凭训练权重编一条最像的

用引用追溯补

8.1.2 · 解决方案

RAG：检索增强生成

为了克服静态知识的局限，RAG 应运而生——生成答案之前，先去外部知识库把相关资料找出来

检索RETRIEVE
从外部知识库
增强AUGMENT
作为上下文
生成GENERATE
BEFORE · 闭卷答题

凭训练权重答

LLM 只靠训练时学到的知识——答得自信，但时效不准、深度不够、容易幻觉，且没有出处。

比喻 · 一个没带资料就上场的学生
AFTER · 开卷作答

检索 + 增强 + 生成

先去外部知识库查最新资料，再把资料融进 Prompt，最后驱动 LLM 作答——兼具准确性与透明度。

比喻 · 翻书查目录 → 摊资料上桌 → 参考答案动笔

HelloAgents 的双轨设计

8.1.3 · 架构详解

记忆系统与 RAG 系统的代码结构

两套系统都采用分层架构，从基础设施到上层工具逐级可插拔

MEMORY · 四层架构

HelloAgents 记忆系统
├── 基础设施层 MemoryManager · MemoryItem · MemoryConfig · BaseMemory
├── 记忆类型层 WorkingMemory · EpisodicMemory · SemanticMemory · PerceptualMemory
├── 存储后端层 QdrantVectorStore · Neo4jGraphStore · SQLiteDocumentStore
└── 嵌入服务层 DashScope · LocalTransformer · TFIDF

工程模式 · 同模块同接口，存储可替换
RAG · 端到端管道

HelloAgents RAG 系统
├── 文档处理层 DocumentProcessor · Document · Pipeline
├── 嵌入表示层 复用记忆系统的 EmbeddingService
├── 向量存储层 QdrantVectorStore（命名空间隔离）
└── 智能问答层 多策略检索 · 上下文构建 · LLM 增强生成

设计要点 · 嵌入服务统一，避免重复实现
